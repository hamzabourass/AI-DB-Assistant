# Customer Order Management System: Database Schema Reference

## System Overview
This document details the database architecture for a comprehensive customer order management system. The system tracks customers, their orders, products, and store information through an integrated relational database structure with five primary entities:

- **Customers**: Stores customer identification and contact information
- **Orders**: Records order transactions with status tracking
- **Order Items**: Contains line-item details for each order
- **Products**: Maintains product catalog with pricing and images
- **Stores**: Manages store location and branding information

## Entity Relationships
- A **Customer** can place multiple **Orders**
- Each **Order** is associated with exactly one **Customer** and one **Store**
- An **Order** contains one or more **Order Items**
- Each **Order Item** references exactly one **Product**
- A **Store** can fulfill multiple **Orders**

### Table: CUSTOMERS
Stores information about registered customers.

#### Columns
| Column Name | Data Type | Constraints | Description |
|-------------|-----------|-------------|-------------|
| CUSTOMER_ID | NUMBER | NOT NULL, PK | Unique customer identifier |
| EMAIL_ADDRESS | VARCHAR2(255) | NOT NULL, UNIQUE | Customer's email (unique) |
| FULL_NAME | VARCHAR2(255) | NOT NULL | Customer's full name |

#### Indexes
| Index Name | Type | Columns | Purpose |
|------------|------|---------|---------|
| CUSTOMERS_PK | Unique | CUSTOMER_ID | Primary key enforcement |
| CUSTOMERS_EMAIL_U | Unique | EMAIL_ADDRESS | Ensures email uniqueness |
| CUSTOMERS_NAME_I | Non-unique | FULL_NAME | Optimizes name-based queries |

### Table: ORDERS

| ORDER_ID | NUMBER | NOT NULL, PK | Unique order identifier |

#### Indexes
| Index Name | Type | Columns | Purpose |
|------------|------|---------|---------|

| ORDERS_STORE_ID_I | Non-unique | STORE_ID | Optimizes store-based queries |

| Column Name | Data Type | Constraints | Description |

| UNIT_PRICE | NUMBER(22,2) | NOT NULL | Price per unit at time of order |

| Index Name | Type | Columns | Purpose |

## Common Query Scenarios

### Customer Purchase History
```sql
SELECT c.FULL_NAME, o.ORDER_ID, o.ORDER_DATETIME, p.PRODUCT_NAME, oi.QUANTITY, oi.UNIT_PRICE
FROM CUSTOMERS c
JOIN ORDERS o ON c.CUSTOMER_ID = o.CUSTOMER_ID
JOIN ORDER_ITEMS oi ON o.ORDER_ID = oi.ORDER_ID
JOIN PRODUCTS p ON oi.PRODUCT_ID = p.PRODUCT_ID
WHERE c.CUSTOMER_ID = [customer_id]
ORDER BY o.ORDER_DATETIME DESC;
```

### Store Sales Summary
```sql
SELECT s.STORE_NAME, COUNT(o.ORDER_ID) AS total_orders, SUM(oi.QUANTITY * oi.UNIT_PRICE) AS total_revenue
FROM STORES s
JOIN ORDERS o ON s.STORE_ID = o.STORE_ID
JOIN ORDER_ITEMS oi ON o.ORDER_ID = oi.ORDER_ID
GROUP BY s.STORE_NAME;
```

### Product Popularity
```sql
SELECT p.PRODUCT_NAME, SUM(oi.QUANTITY) AS total_quantity_sold
FROM PRODUCTS p
JOIN ORDER_ITEMS oi ON p.PRODUCT_ID = oi.PRODUCT_ID
GROUP BY p.PRODUCT_NAME
ORDER BY total_quantity_sold DESC;
```
